# 13-有界诊断与独立关键反馈

让大量普通诊断保持容量上限，同时保留任务完成、失败等关键反馈。诊断滚动不触碰关键反馈文件。

这是根据工程问题重新编写的标准库参考实现。所有演示为合成事件，不包含历史生产日志、设备地址或公司代码。

## 快速运行

Python 3.10 或以上，无第三方依赖。在本仓库目录运行：

    python demo.py
    python -m unittest discover -s tests -v

演示向临时目录写入 30 条普通事件和一条大事件，检查条数、UTF-8 字节数和关键反馈保留情况。退出后临时目录清理。

## 两条保存路径

| 文件 | 内容 | 保留方式 |
|---|---|---|
| diagnostics.jsonl | 普通阶段、耗时、调试说明 | 同时受条数和 UTF-8 字节数限制，整条移除最旧记录 |
| critical-feedback.jsonl | 任务完成、失败及其他关键证据 | 独立追加并同步落盘，不自动滚动、摘要或删除 |

append_diagnostic 对序列化后的完整记录计费，包含字段开销和换行。超出单条预算时只保留原事件字节数和 SHA-256 摘要，不把整段大文本塞进尾部。重新以更小预算打开日志时，也会收紧普通诊断。

append_critical 要求调用者提供稳定的 event_id。相同身份和相同内容返回 DUPLICATE；同一身份内容冲突则明确报错。关键反馈不受普通诊断容量限制，也不会被自动摘要。

## 文件和方法

- bounded_log.py：有界诊断、独立关键反馈、幂等和损坏检查。
- METHODS.md：容量口径、错误语义、可恢复性及规模取舍。
- demo.py：可直接运行的纯合成演示。
- tests/：字节和条数边界、Unicode、大事件、重启保留、冲突、损坏及写入失败测试。

## 使用边界

每个目录由一个进程/实例独占写入。同一实例中的线程调用有锁；没有跨进程锁。关键反馈文件会持续增长，保留期限、备份和归档由业务另行管理，不能直接删除整个目录来清理诊断。

fsync 或写入失败会抛出错误。发生错误时，数据可能已经部分或全部写入；必须按 event_id 重试核对，不要据异常推断“绝对没写”。不完整尾记录和非 JSON 数据会报错，本实现不会静默删尾修复。

普通诊断的磁盘文件大小有界，不代表整个 Python 进程内存、磁盘总容量或延迟有硬上限。关键反馈扫描采用简单线性实现，适合说明方法；大规模业务可采用事务数据库和独立归档。
